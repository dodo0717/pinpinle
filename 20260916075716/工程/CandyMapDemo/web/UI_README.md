## 1. 全局适配规则（所有页面必须遵守）

- **固定逻辑画布**：`#stage` 是 `1080 × 1920`（9:16）的盒子，由 JS `fitStage()` 按可视高度算 `fitScale` 等比缩放铺满视口（`transform-origin: top left`，居中到"扣掉系统手势安全边"的区域）。**所有 UI 尺寸都写在这个 `1080×1920` 坐标里**，不要用 `vw/vh/%` 去适配——和工程里其它屏（如结算弹窗 `.dialog-card { width: 720px }`）保持一致。
- **配色板（来自设计图，主页/弹窗通用）**：

  | 用途 | 色值 |
  | --- | --- |
  | 奶油底 / 牌面 | `#FFF8E7` → `#fdeccb`（渐变） |
  | 金（描边/高亮/边） | `#F5C542` / 深金 `#D9A227` |
  | 棕（昵称/体力胶囊/关卡号字） | `#6B4A2F` |
  | 橙（选中难度） | `#FF6B35` |
  | 灰（未选难度） | `#5A5A5A` |
  | 深底（底栏） | `#2E2E40` |
  | 绿（加体力/Play） | `#4CD964` / 渐变 `#6BE36B`→`#37B84A` |

- **底部导航栏**是浮层（`z-index:70`），覆盖在所有屏之上；弹窗再压一层（`z-index:90`）。功能浮层自己用 `inset` 让出底栏位置，普通屏用 `.screen:not(#screen-game):not(.sheet) { padding-bottom: 132px }` 留白。
- **z-index 层级约定（所有浮层必须遵守，避免互相遮挡）**：

  | 层级 | z-index | 说明 |
  | --- | --- | --- |
  | **排行榜（整屏）** | 12 | 2026-10-22 起排行榜改**整屏**（不再是 sheet 浮层），盖过主页地图（10） |
  | **图鉴（整屏）** | 12 | 2026-10-22 起图鉴同样改**整屏**（大图预览仍是浮层，叠在其上） |
  | scrim 遮罩 | 64 | 打开 sheet 浮层时的半透明压暗层（现只服务大图预览/设置） |
  | 功能浮层 sheet（大图预览/设置） | 65 | 整张卡片式浮层（排行榜、图鉴已移出这一档） |
  | 底部导航栏 tabbar | 70 | 常驻最底栏，覆盖所有屏 |
  | 结算吊牌 result-preview | 89 | 低于 #dialog，让"看广告/续命"能盖住它 |
  | PLAY 吊牌 level-preview / 通用弹窗 #dialog | 90 | 最高交互层；通用确认/广告弹窗留在这里 |

  > 规则：**新弹窗要么复用 `level-preview`(90) 要么用 `#dialog`(90) 或 `result-preview`(89)，不要新起一个 z 值插在中间**。需要"盖在结算之上"的（如广告、续命确认）必须 ≥ 90。

- **字体（强制，来自项目永久指令）**：一律使用**免费商用字体**，当前统一 **HarmonyOS Sans SC**；**禁止**引入任何需要付费授权的字体。注意微信小游戏包体限制，字体文件**不宜全量打包进主包**（两个 ttf 约 16MB 会顶穿上限），需走**远程加载或子集化**。

## 3. 页面二：关卡详情 / 开始弹窗（PLAY / Level Preview）

**设计依据**：`PLAY UI.png`——点关卡节点后弹出一块"从屏幕上方吊下来"的牌子（麻绳悬挂 + 下落动画），盖在地图背景上；牌子内选本关 PLAY 模式，再点 Play 进入三消棋盘。它**不是三消棋盘本身**，是进局前的前置弹窗。

**视觉构成（吊牌从上到下）**：
- 麻绳：从屏幕顶垂下，连到牌子上沿（高度由居中自动撑开，不计入牌尺寸）。
- 关卡号：`第 N 关` 金色描边大字。
- 难度切换：`简单` / `困难`（同主页灰/橙/金逻辑，当前模式高亮）。
  - ⚠️ **困难模式有门槛（2026-10 新增规则）**：**同一关必须先在简单模式拿到 3 星**，才允许选它的困难模式。点困难按钮会提醒「**三星通关后开启困难模式**」。
    - 判定：`web/main.ts` 的 `nightmareUnlocked(level)` = 跨模式查 `progressByMode.normal` 里该关的 `stars >= 3`（两套进度独立存，见核心 `progress.ts`）。
    - 三处统一拦截：①PLAY 弹窗困难按钮置灰挂锁（`🔒 困难`）+ 显示「三星通关后开启困难模式」（`levelPreview.ts` 的 `canNightmare` 回调）；②地图节点在困难模式下未达门槛即置 `locked`，点击提示 `MAP.nightmareLocked`（`mapView()` 带 `lockNote`）；③点 Play 进关前再兜一次（`onPlay` 守卫）。

> - **结算记分口径（2026-10 改）**：结算弹窗显示的**本关分数 = 该模式下「本关历史最高分」**（`personalBest`，`Math.max` 取最大），**不是本局分、也不是累计分**；标签按当前模式显示 `简单分数` / `困难分数`（`main.ts` 的 `levelBestScore()` / `scoreLabelOf()`，胜利 / 失败 / 续命三张弹窗统一）。两套进度分开存，所以简单分与困难分互不相干。
> - **「下一关」改走 PLAY 弹窗**：结算里点「下一关」**不再直接进关**，而是 `exitToHome()` 回主页 + `levelPreview.open()` 弹该关详情页（体力在点 Play 那一刻才校验）。默认模式规则（`openNextLevelPreview()`）：该关困难**没开启** → 默认**简单**；已开启 → 默认**玩家上次选的模式**（`mode` 全局且落盘，就是上次选择）。
- 星级目标：`1星 X分 | 3星 Y分`（读设计表 `STAR_LINES_BY_MODE[mode][level]` 的 1星/3星）。
- 绿色 `Play` 大按钮（圆角胶囊，绿渐变，白字）。
- 右上角 `✕` 关闭；点牌外空白也关闭。

**实现做法**：
- 新增独立模块 `web/ui/levelPreview.ts`（`createLevelPreview`），只负责弹窗 DOM、开/关、难度切换、动画；**不反向依赖 `main.ts`**（避免循环导入）。
- **居中方式**：`.lp-drop` 是占满整屏高度（`height:100%`）的 flex 列 = `绳子(flex:1)` + `牌(flex:0 0 auto)` + `底部占位 .lp-spacer(flex:1)`，于是牌子在整屏**垂直居中**，绳子自动填满上方、不计入牌尺寸。
- **下落动画**：`@keyframes lp-drop` 从 `translate(-50%,-170%)` 带轻微回弹落到 `0`；每次 `open()` 先移除 `.on` 再强制重排再添加，重启动画。
- **数据来源**：星级直接读 `STAR_LINES_BY_MODE[mode][level]`；难度切换走 `main.ts` 的轻量 `applyMode()`（只改全局 `mode` + 重建关卡/刷新地图，**不触发** `setMode` 的"回主页 + 清局 + toast"副作用）。
- **选关流程接线**（`web/main.ts`）：
  - `homeScreen.onPick(level)` 不再直接进局，而是 `levelPreview.open(index, level, mode)`（index=playable 下标，level=关卡号）。
  - 弹窗 `onPlay(i, m)` → `applyMode(m)` + `levelPreview.close()` + `loadLevel(i)`（走原进局路径：体力预扣/转正、断点、存档、切屏）。
  - 弹窗元素挂在 `stage`（浮层，`z-index:90`），`showScreen` 不会误关它。
- 尺寸（1080×1920 坐标）：牌宽 `820px`（屏宽 76%）、内边距 `72/56/82`；字号关卡号 96 / 难度 40 / 星级 52（数字 60）/ Play 62。

**涉及文件**：`web/ui/levelPreview.ts`（新增）、`web/ui.css`（`.level-preview` / `.lp-*` 全部样式）、`web/main.ts`（import、applyMode、onPick 改 open、挂 `levelPreview.el`）。

## 4. 页面三：结算弹窗（胜利 / 失败）

**设计依据**：`胜利弹窗UI.png` / `失败弹窗UI.png`——倒计时归零后，一块带麻绳的牌子从屏幕上方"吊下来"，盖在三消棋盘上。分为胜利（奖杯/皇冠）与失败（灯泡）两种。

**视觉构成（吊牌从上到下，与 PLAY 同骨架）**：
- **顶部英雄图标（变化图标）**：胜利=奖杯 🏆 / 皇冠 👑（随荣誉档位 `god/king`），失败=灯泡 💡；优秀档不画图标改用三颗星（按实际星级点亮）。图标暂用 emoji 占位，美术出图后换 `<img>`。
- **主标题**：金色描边大字（胜利各档不同：超神/王者/优秀；失败=`差一点就成功了`）。
- **副文案**：图标/标题下方、得分上方（仅胜利有，如"您的分数超越了 X% 的玩家"）。
- **得分卡（固定底框）**：米色圆角底，含"本关得分"标签 + 大号金色数字（从 0 滚上去）+ 辅助文案。
- **按钮（绿=主、灰=次）**：
  - 胜利：`下一关`(绿) / `再战本关`(灰)；超神档额外加 `查看排行榜`(灰)。
  - 失败：`再战本关`(绿) / `看广告+1体力`(灰) / `返回主页`(灰)。

**实现做法**：
- 新增 `web/ui/result.ts`（`createResultPopup`）：**复用 PLAY 的吊牌骨架**（`.lp-drop`/`.lp-rope`/`.lp-card`/`.lp-spacer`），所以**尺寸（宽 820）与居中方式、绳子另算高度，和 PLAY 完全一致**。仅换内部 `.rs-*` 内容；结算是终态、原本刻意「没有关闭按钮、点空白不关」，但**现卡片右上角加了 `✕` 关闭键（`.lp-close`，与 PLAY 同款），点它 = 隐藏吊牌并调用 `onHome` 回主页**（由 `main.ts` 三处 `resultPopup.show` 统一传 `exitToHome`），作为统一的逃生口，体验与其余浮层一致。
- `z-index: 89`：低于通用弹窗 `#dialog`(90)，这样"看广告/续命"能盖在结算之上。
- 按钮沿用通用弹窗的 `DialogButton[][]` 口径（含 `dim` 置灰+提示语义），所以**体力扣费、续命广告、排行榜返回等行为原样保留**，只换了外衣。

**14. 地图果冻珠立体化（2026-10-22，用户反馈「珠被背景盖住不突出」；同日迭代五版，最终对齐豆包参考图）**
> 阅读顺序：改版一（原始思路）→ 二 → 三 → 四 → **改版五（最终形态，珠体自绘 + 外发光）**。下面按「最终形态在前、迭代教训在后」排列，改代码以**改版五**为准。

- **改版五（最终形态，用户给了豆包参考图）**：参考图的精髓 = **珠体是浓郁的不透明渐变（顶亮→中饱和→底深）+ 同色系外发光（backlit 发光果冻）**，素材只当纹理。此前一直失败是因为在**提亮浅色素材**——浓度永远到不了。实现：
  - `.node-gel` 变成**自绘不透明珠体**：`linear-gradient(top→mid→bot)` 三态浓郁配色（蓝白 / 糖果粉 `#ffeef8→#f99ad2→#cf3d90` / 黄金 `#fff8d6→#ffc63e→#ee7c00`）+ 左上大白高光（两层 radial）+ 底部透光（`--gel-lower`，背光果冻感）。
  - **外发光**（突出的主力）：`box-shadow` 两层同色光晕（贴身较实 + 外扩大而淡，`--glow/--glow2`），跟 gel 的 `border-radius:50%` 圆走、**不读切图 alpha** → 无毛边。
  - `.node-art`（素材切图）改 `mix-blend-mode: multiply` 当纹理：素材白色珠体透出 gel 渐变，星冠/气泡/描边深色细节保留；素材浅底色不再决定珠色。锁定灰化移到 gel（`grayscale(.82)`），multiply 的纹理跟着一起灰。
  - 接触阴影再减淡（发光珠地上主要是光不是影）。
  - ⚠️ 关键认知修正：前几版「叠色=脏」错在往**浅色素材**上叠**半透明**色；改成「不透明自绘珠体打底 + 素材 multiply 当纹理」后，浓郁且不灰。
- 实测：金/粉/蓝白三态珠浓郁发光、星冠纹理透出、数字清晰、零异常。
- **改版一（原始方案）**：问题 = 三种珠切图（`node-todo/star1/star3`）本身是平的，压在底图上没有体积感，颜色又和背景接近。方案（纯 CSS，不动切图，三态共用一套结构）：
  - **`.node-gel` 果冻层**（`map.ts` 每颗珠插入一个 span，插在数字/锁/宠物**之前**让它们叠在上层）：自下而上五层半透明渐变 —— 竖向色泽渐变（三态各自色相：蓝白 / 糖果粉 / 金，CSS 变量 `--gel-top/mid/bot`）+ 边缘暗角（球体曲率，`--gel-edge`）+ 底部环境反弹光（`--gel-bounce`）+ 顶部大高光 + 左上高光点。半透明（alpha 0.4~0.6）保证切图里的星星/皇冠/纹理透出来。
  - **珠外光环**：`.node-gel` 的 box-shadow 套一圈暗环 + 一圈亮环，把珠从底图里「抠」出来。
  - **投影**：`.map .node` 两层 `drop-shadow`（贴地接触影 + 远距离软影，轮廓跟切图 alpha 走）；`::before` 画珠下压扁椭圆接触阴影（AO，没有它珠是飘的）。⚠️ `.node.locked` 原有的 `filter: saturate()` 会整条覆盖 filter，必须把 drop-shadow 一并重写进去。
  - **`isolation: isolate`**：果冻层只与珠自身混合，不跟地图底图串色。
- **改版四（同日，用户反馈「还有毛边小幅黑边」——根因排查过程值得记）**：
  1. 先像素级体检素材：三张切图 200×200，边缘半透明像素平均亮度 149~175（`semiDarkPct` 仅 5~6%），**素材边缘不是黑的，也不存在黑色描边**（`opaqueDarkPx=0`）；运行时清点也确认 `.node` 背景 `none`、filter `none`，珠上只有一层切图（不是「旧图没删、新图往上盖」）。
  2. 真正的黑边来自两个**基于 alpha / 贴边**的东西：① `drop-shadow` 按 alpha 通道算，切图缩放后那圈 1px 抗锯齿边会被整圈染成暗边 —— 已删，阴影改用纯 CSS 渐变椭圆（不读 alpha）；② `contrast(1.08)` 压深了素材自带描边 —— 已删，只留 `saturate(1.5) brightness(1.18)`。
  3. 还有一次我自己踩的：把接触阴影放大到 `1.5×0.6nd` 后暗斑爬上珠身、盖住珠下部约 40%，看着就是脏边 —— 收回到 `0.95×0.24nd`、中心落在珠底下方 `0.12R`（实测暗区只侵入珠底 `0.039R`，只压接触点）。
- **改版三（同日，用户反馈「黑圈圈底框很脏」）**：珠外暗环（box-shadow 暗色外圈）、边缘暗角（radial 暗色到珠缘）、inset 暗部、以及**贴边小模糊的 drop-shadow**（等于给珠描一圈黑边）全部删掉。现在只有：白高光点 + 顶部柔光 + 底部反射光 + 一道细白亮环（分离用）+ **单层远距离柔影**（offset 大、blur 大、alpha 低——落影不是描边）；接触阴影（AO）也减淡到 .42。铁律：**珠上一切暗色叠加都会显脏，立体感只能用「提亮」和「远距离柔影」做**。
- **改版二（同日，用户反馈「越改越脏」——重要教训）**：第一版往珠上叠三态彩色半透明渐变，本质是**染色**，颜色一叠就发灰发脏。改为：**珠的颜色只来自素材原图** —— 切图挪到独立 `.node-art` 层（`--art` 变量按三态给图），`filter: saturate(1.55) brightness(1.16) contrast(1.08)` 只作用在它身上（单独一层是为了不把数字/🔒/宠物一起过曝）；`.node-gel` 只留**白色高光 + 中性暗角 + 底部反射光 + 珠外暗环亮环**，零色相。锁定灰化也移到 `.node-art`（`saturate(.18)`），`.node.locked` 不再整颗套 filter（避免顶掉 drop-shadow）。
- ⚠️ 经验：**立体感靠「光」（白高光/中性暗角/投影），珠色靠素材原图提纯**；往切图上叠彩色半透明层 = 脏。粉/蓝白珠是素材原色偏浅，CSS 提纯上限到此，要更艳需换素材。
- 实测：四态同屏（金/粉/蓝白/锁定灰）全部生效（12 节点 × art 层 + gel 层 + AO + 双投影），零 JS 异常。

**26. 教学改为「每一步都要玩家操作才推进」（2026-10-28，用户要求）**

- **其余步骤本来就是玩家驱动的**，逐条核对过：step 1 拖动（输入锁 + 落点锁，不动就不走）、step 2 旗子（`onNext`）、step 4 整片拖拉（`tutorialAfterMove` 里玩家移动才 step=5）、step 5 自由拼够 3 组才 `finishTutorial()`。困难序章不讲时间，step 2 点继续后直接进自由拼。

- **顺带修好「整片拖拉」演示不到的问题（同一轮，用户建议"序章完全可以控制初始生成成片"）**：`tutorialStepGroup()` 要找一块**≥2 格的融合组**来演示，但原教学盘只手工摆了「3 缺 1」，而那 3 块在第一组拼成时**就被消除了** —— 场上剩下的全是随机散块，实测 `mergeGroups()` 返回 12 个单格组 → 这一步**永远被跳过**。

  1. 用户交付 8 秒动效视频（720×1280 **HEVC**）→ Chrome/Edge 都解不了（系统无 HEVC 扩展），**装 ffmpeg 才解码成功**（winget 装 Gyan.FFmpeg，取帧/转码都能用）；

  3. ⚠️ 但视频与底图是**两次独立 AI 生成，构图/几何对不上** —— 客观验证（不靠肉眼）：

       但**匹配到的位置与视频里的相对位置完全对不上**（视频左上的云 → 底图搜到右中部）= 色块偶然相似。
     → 结论：**不能整块盖上去**（节点位置会错、两张画打架）；
  4. 全画面序列帧也不可行：24 帧 ≈ 44MB 解码内存，手机吃不消。
- **视频的最终用法 = 光影混合层（`mix-blend-mode: soft-light` + opacity 0.5）**：
  底图保持自己的画风，只吸收视频里的**明暗流动**（云飘过、水波闪、风车转动的光影）——
  **不需要几何对位**，也不会出现两张画打架。强度在 CSS/JS 里一行可调（觉得脏就调低，或改 `screen` 只提亮）。
- **HEVC → H.264 转码**：源文件是 H.265（`hvc1`），Safari/有硬解的 Chrome 才能播。已用 ffmpeg
  （winget 装的 Gyan.FFmpeg 9.0.2）转成 **`xiaozhen-anim.mp4`（H.264，720×1280，8 秒，0.9MB —— 比原 1.9MB 还小）**，

- **最终方案 = 零素材程序化动效（新文件 `web/ui/map-fx.ts`）**：canvas 粒子叠在底图上、节点之下 ——
  - ① 云影（3 团柔光缓慢平移）② 樱花瓣飘落（18 片）③ **喷泉水花**（抛物线水滴，位置对准底图右下喷泉 0.833/0.758）④ 水面波光（河面闪烁光点）⑤ 光尘；
  - **半分辨率 canvas**（768×2731，`ctx.scale(0.5)`）—— 全分辨率 33MB 位图内存，半分辨率无观感差异；
  - ⚠️ `buildWorld` 每次 render 重建 DOM，**旧动效循环必须先 `destroy()`**（cancel rAF），否则空转泄漏；
  - 角色/风车的"真动作"（挥手/旋转）**需要序列帧或抠图**，本轮未做（待办）。
- **`ROAD_X` 重标**：新图是宽土路，自动检测条件改成「暖色偏亮」（r≥g≥b 且都亮）+ 目视校对；图底 y>3100 路到头是池塘码头 —— **第 2 关手工定在码头（x≈0.35）、第 1 关在右下岸边（x≈0.86）**。
