## 五、【本次 bug 正本清源】"掉图规则没移植"的真相

### 5.1 规则层没丢

`core/engine.ts:452-468` 的 `resolveBoard()` 是完整的：

```452:468:assets/scripts/core/engine.ts
for (const cell of group.cells) this.grid.setAt(cell, null);   // 消除
const afterEliminate = this.grid.toArray();                      // 快照
collapseColumns(this.grid);                                      // 下压
if (this.grid.emptyIndices().length > 0) {
  const result = refillGrid(this.grid, this.config.imageIds, this.rng);  // 补位
```

棋盘数据一直是对的。

### 5.2 渲染层把它藏了

原版 `main.ts:1497-1531` 的掉落反推算法，移植版 `GameBootstrap.playCollapse()` **算法一致**（都用碎片 ID 在 `afterEliminate` 帧里反查原格），
差距只在一处 —— `BoardView` 的**可见性复位**：

| | 原版（DOM/CSS） | 移植版（Cocos Node） | 后果 |
|---|---|---|---|
| 消除消失 | CSS `@keyframes vanish` 播完，`opacity:0 scale(.1)`，**元素还在** | `playVanish` 里 `ref.root.active = false` + `scale 0.2` | 格子被**关掉** |
| 补位时恢复 | `paintBoard(finalData)` 重绘，**元素自然复用** | `setCellFace()` 只换 `spriteFrame`，**从不复位 `active`/`scale`** | 新块**隐身** |

即：CSS 动画不改元素存在性，Cocos 的 `active=false` 是硬开关，而移植时**没人在补位时把它打开**。

已修（`BoardView.setCellFace`）：
```ts
ref.root.active = pieceId !== null;
ref.root.setScale(1, 1, 1);
this.paintFace(i, pieceId);   // 拆出只管贴图的方法，供异步加载回调使用
```
拆 `paintFace()` 的理由：贴图是异步 `resources.load` 的，回调若走 `setCellFace` 会在消除动画播到一半时把格子复位，打断动画。

### 5.3 但"消除动画"本身也只做了 6 个阶段里的 3 个

原版（§6.3 / §11.6.2）**5 阶段 + 飘字 + 掉落 = 6 段**：

| 阶段 | 原版 | 时长 | 移植版 |
|---|---|---|---|
| 移动完成帧 | `paintBoard(afterMove)` | 90ms | ✅ 有 |
| ① 识别 | 整组抬起 4px + 金环 | 60ms | ❌ 无 |
| ② 拼合 | 落回原位（缝合上） | 50ms | ❌ 无 |
| ③ 确认 | 一顿 `scale 1.07` | 40ms | ❌ 无 |
| ④ 消除 | 鼓起→炸金光→缩没 | 350ms | ⚠️ 有（简化：只缩到 0.2） |
| ⑤ 得分飘字 | `+N` 飞向 HUD + HUD bump | 500ms 并行 | ❌ 无 |
| ⑥ 掉落/补位 | fall(压扁回弹) / spawn(淡入) | 260+12·cols | ⚠️ 有（无压扁/无淡入） |

**①②③ 是"融合"这件事的全部说服力** —— 原版注释写得明白：
"4 块必须**同时**进入同一阶段，差一帧就会被看成『有一块没跟上』，而融合的全部说服力就在『这 4 块是一个整体』"。
现有代码跳过了这三段，玩家看到的是"4 块直接没了"，不知道刚才发生了什么。

### 5.4 掉落动画的视觉差异

| | 原版 | 移植版 |
|---|---|---|
| `fall` | `translateY(--dy) scaleY(1.05)` → 72% `scaleY(.93)` 压扁 → 弹回 1 | 只有位移，**无落地压扁** |
| `spawn` | `scale(.9) opacity:0` → 55% `opacity:1` → `scale(1)` | 只有位移，**无淡入**（新块和老块看起来一样） |
| 错开 | 结算掉落按列 `(index%cols)*12ms`；开局入场按格 `i*18ms` | 结算用 `index%cols`，入场需确认 |
| 强制重排 | `void boardEl.offsetWidth`（防多画一帧闪一下） | 无对应机制 |

## 八、一句话结论

**算法层是完整的，游戏"能算对"；表现层只移植了 24%，所以"看不出在玩什么"。**
本次掉落 bug 是这 24% 里的一个具体病例：规则没丢，是 Cocos 的 `active=false` 没有被复位 —— 已修。
但**消除动画 6 段只做了 3 段**、**体力/存档/结算/引导/音效全缺**，这才是"没法玩"的根因。
