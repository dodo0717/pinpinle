## 0. 一页速览

| 项 | 结论 |
|---|---|
| 名称 | 统一叫**「序章」**（不再叫新手引导 / 教学关） |
| 形态 | **独立关卡 `level 0`**，不占 60 关编号 |
| 教学核心 | ⭐ **不是讲概念，是做一个动作**：开局摆出「**3 缺 1**」的局面，玩家**拖一块过去**就拼成、立刻消除（一步成功，教的是"拖动"本身） |
| HUD 认知 | ⭐ **聚光灯（Spotlight）强制引导**：讲到「目标旗 / 倒计时」时，全屏压暗 + **挖洞圈住那个元素** + 一句说明，玩家视线被强制带过去，点「知道了」才继续 |
| 排版 | ⭐ 抽屉 / 提示条按 §9 规范**重做**（卡片分区 + 真实插图 + 字号层级），不再是纯文字堆叠 |
| 内容 | 简单序章 5 步（拖一块拼合 → 目标旗 → 倒计时 → 整片拖拉 → 完成）；困难序章 4 步（挪一格 → 拖一块 → 目标旗 → 完成） |
| 目标 | 达成 **3 星（= 3 组）** 结束；中途达成 1★/2★ 给轻提示 |
| 时间 | 序章**全程不计时**（倒计时灰显冻结）；讲倒计时那一步**演示走 3 秒**再冻回 |
| 产出 | **不进排行榜、不进图鉴星数、不扣体力、不存档断点** |
| 入口 | 首页顶栏**右侧**胶囊「教学」→ 右侧抽屉（怎么玩图解 + 重玩序章） |
| 消失条件 | 困难模式**累计通关 ≥ 10 关**后，首页按钮隐藏（设置页永久保留） |

### v2 相对 v1 的三条大改（用户反馈）

| # | v1 的问题 | v2 的做法 |
|---|---|---|
| 1 | **全是文字，没教"怎么拖"**：S1 文案「把同一只萌宠的 4 块拼到一起」，玩家要自己理解、自己找 4 块、自己挪好几步 | 开局**手工摆出「3 缺 1」**：3 块已成 L 形、缺的 1 块就在旁边 → 手指/箭头动画指着它 → **拖一步就拼成并消除**。教的是动作本身 |
| 2 | **排版难看**：抽屉是"标题 + 两行状态 + 两个大按钮 + 四行文字说明"的裸列表 | 按 §9 重做：分区卡片、**用真实贴纸画的"3缺1"插图**、字号/间距层级、按钮主次分明 |
| 3 | **倒计时、目标旗的作用只是"提一句"**，玩家不看 | 讲这两样时开**聚光灯**：全屏压暗、只留那一个元素亮着，**强制看过去**才继续；倒计时还**真的走 3 秒**给我看 |

### v3 再收紧（2026-10-26，用户："不要用文字教学，要强制教用户拖动，只有拖动这碎片可以操作，动画模拟滑动"）

| # | 要求 | v3 做法 |
|---|---|---|
| 1 | **不要用文字教学** | 序章棋盘内**一个字都没有**：删掉全部教学横幅 / 气泡（`step1 / step2 / star1 / star2 / step4 / 旗子文案 / 时间文案`）。只留两处非教学文字：抽屉里的「怎么玩」图文（玩家主动点开）、完成弹窗的结算说明 |
| 2 | **强制教拖动** | **输入锁定**：教学步内**只有目标那一块能拖**，其余块压暗且不响应（按了会抖一下 + 目标块脉冲）；**只能落到缺口**，落到别处直接回弹 |
| 3 | **只有拖动这碎片可以操作** | 同上：`onPointerDown` 非目标块直接 `return`；30 秒还没做成 → 降级解锁（防卡死） |
| 4 | **动画模拟滑动** | 循环播放 **1.6s 的滑动演示**：手指按住目标块 → 沿直线滑到缺口 → 影子落位 → 4 块拼合**金光脉冲** → 复位循环；**玩家一按就停**，3 秒无操作重播 |

> ⚠️ 一句话概括 v3：**把"告诉他怎么做"换成"让他只能这样做"** —— 文字退场，强制 + 动画接管。

## 1. 背景与目标

- **背景**：现有五步引导气泡（swap / hint4 / eliminate / refill / clear）已在 2026-10-25 全部关闭（`main.ts` 的 `showGuide()` 直接 return），原因是用户反馈"拼图开始和过程中冒文字说明"。所以教学**不能**做成中途弹字的形式。
- **目标**：
  1. 新玩家在**不打断、不计时、不算成绩**的环境里学会：怎么拼、怎么整片拖、目标是什么、时间意味着什么；
  2. 老玩家随时能从首页抽屉重看 / 重玩；
  3. 学会之后教学入口**自动消失**，不长期占屏。

---

## 2. 名词与定位

| 名词 | 定义 |
|---|---|
| 序章 | 独立的教学关卡，**不属于 60 关**，编号记作 `level 0`；分「简单序章」「困难序章」两版 |
| 组 | 消除单位：同一只萌宠的 **4 块**按正确相对位置拼成 2×2 → 消除 +1 组（+1 分） |
| 整片 | 已拼合的融合组；拖动时整片刚性平移，不会散 |
| **3 缺 1** | v2 核心局面：某只萌宠的 **3 块已拼成 L 形**、缺的 **1 块就在旁边**，玩家**拖一步**就拼成 2×2 并消除 |
| **缺口** | "3 缺 1"里缺的那一格；画虚线呼吸框 + 目标块的手指拖入动画 |
| **聚光灯** | Spotlight：全屏压暗 + 挖洞只留一个 HUD 元素亮着 + 一句说明，**强制把玩家视线带过去**（§9.2） |
| 教学步 | 序章内的最小教学单元（一个目标 + 一句短语 + 一个视觉提示），完成即进入下一步 |

## 3. 与现有系统的边界（序章不进哪些系统）

| 系统 | 是否参与 | 说明 |
|---|---|---|
| 60 关进度 / 解锁链 | ❌ | 序章不影响 `progress.unlocked`，也不在地图上推进度 |
| 排行榜（总分榜 / 关卡榜） | ❌ | 序章不写 `progressByMode` → 天然不入榜 |
| 图鉴星数（每 10 星解锁一张） | ❌ | 序章的 1★/2★/3★ 只是**教学内进度**，不入档 |
| 体力 | ❌ | 进序章**不扣体力**（`enterWithStamina` 走旁路） |
| 断点续玩 / session | ❌ | 序章不落 `session`，退出或刷新从第 1 步重来 |
| 广告（续命 / 加体力） | ❌ | 序章内不出现任何广告入口 |
| 失败结算 | ❌ | 时间不走 → 不存在超时失败 |
| 音效 / 动画 / HUD | ✅ | 与正式关一致（保留手感） |

> ⚠️ 图鉴是「每 10 颗星解锁一张」，若序章的 3 星入档会打乱解锁节奏 —— 所以必须隔离。

## 4. 触发 / 结束 / 隐藏

### 4.1 首次触发
- 判定：存档 `tutorial.seen === false` 且 `困难模式累计通关 < 10`。
- 行为：进入首页时**自动展开一次右侧抽屉**（不是强制进关），玩家点「开始教学」才进序章；关闭后 `seen = true` 落盘，不再自动展开。

### 4.2 主动进入
- 首页右侧「教学」胶囊 → 抽屉 → 「重玩简单序章」/「重玩困难序章」。
- 困难序章需**简单序章已达成 3 星**（沿用现有「同关简单三星才开困难」的门槛口径），未达成时按钮置灰并提示。

### 4.3 结束
- **完成**：达成 3 星 → 完成弹窗 → 标记 `normalCleared / nightmareCleared = true`。
- **跳过**：右上角「跳过教学」→ 直接退出序章，只标记 `seen = true`（不标记完成）。

### 4.4 隐藏
- 条件：**困难模式累计通关关数 ≥ 10**（`progressByMode.nightmare` 中有记录且 `stars > 0` 的关卡数）。
- 命中后：首页「教学」胶囊不再显示（设置页是否保留重看入口，见 §14 待定项）。

## 5. 教学流程

### 5.1 简单序章（5 步）

> 设计原则（v3）：**不写一个字，只让他做出那个动作**。
> ① 盘面摆成"3 缺 1" → ② **动画循环演示"手指按住 → 滑到缺口 → 拼合发光"** → ③ **锁住输入：只有那一块能拖、只能拖到缺口** → ④ 玩家一上手就会，做完才解锁。
> 讲 HUD（旗子 / 时间）同样**零文字**：聚光灯挖出来，让**元素自己动**（数字跳变 / 真走 3 秒），看懂靠看，不靠读。

| 步 | 教什么 | 触发 | **文案** | 视觉 / 强制 | 完成判定 |
|---|---|---|---|---|---|
| **S1** | **拖动（3 缺 1）** | 进关即开始 | ⛔ **无** | ⭐ 手工摆好的「3 缺 1」+ **循环滑动演示动画**（手指 + 碎片影子滑进缺口 + 拼合闪光）+ **输入锁：只有那块能拖、只能落到缺口** | 拖进缺口 → 4 块成 2×2 → **立刻消除 +1 组** |
| **S2** | **目标旗**（强制看） | S1 消除后立刻 | ⛔ **无** | ⭐ 聚光灯只亮 `#hud-goal` → 旗子数字 `3` **跳变到 `2`**（刚拼的那组立刻反映在旗子上） | 点亮的旗子 / 点暗区外的「继续」箭头 → 关闭 |
| **S3** | **倒计时**（强制看） | S2 结束 | ⛔ **无** | ⭐ 聚光灯只亮 `#hud-timer` → 数字**真的从 03:00 走到 02:57**（3 秒）→ 冻回 03:00 并灰显 | 3 秒后自动关闭 |
| **S4** | **整片拖拉** | S3 结束 | ⛔ **无** | ⭐ 同一套机制：圈住一个 ≥2 块的片 + 滑动演示动画 + **只准拖这一片** | 一次成功的整片移动 |
| **S5** | **完成** | 累计 3 组 | 完成弹窗（**结算说明，不是教学文案**） | 弹窗（§6） | 达成 3 星即结束 |

> **"零文字"的边界**（要写清楚，免得后面又加回文字）：
> - ⛔ **序章棋盘内零文字**：不出现任何教学横幅 / toast / 气泡 —— 一个字都没有；
> - ✅ **抽屉里可以有图文**：那是玩家**主动点开**的说明书，不是拼图过程中的打断；
> - ✅ **完成弹窗可以有三行说明**（倒计时 / 排行榜 / 图鉴）：那是**结算信息**，不是教学。

**为什么 S1 要"3 缺 1"而不是"给你 4 块自己拼"**：
- v1 的 S1 只说「把 4 块拼到一起」—— 玩家要**自己找**是哪 4 块、还要**自己想**往哪挪，新手第一次往往挪 3~4 次还拼不成，挫败；
- "3 缺 1"把思考量压到 **0**：缺口在画面上明摆着，缺的那块就在旁边，**一步到位 + 立刻消除**，玩家第一秒就懂了"哦，拖过去就拼上"；
- 教的是**拖动这个操作本身**（按住、移动、松手），而不是"拼图"这个抽象概念 —— 这正是 v1 缺的。

**"3 缺 1"盘面的构造**（`buildTutorialGrid()`，见 §8）：
```
┌───┬───┬───┐        ┌───┬───┬───┐
│ ▓ │ ▓ │ ? │        │ ▓ │ ▓ │   │   图例：▓ = 该萌宠已拼好的 3 块（L 形）
├───┼───┼───┤   →    ├───┼───┼───┤         ◻ = 缺的那块（就在旁边，一步可拖）
│ ▓ │ ◻ │   │        │ ▓ │ ◻ │   │        ⬚ = 缺口（虚线呼吸框）
├───┼───┼───┤        ├───┼───┼───┤        ?  = 其它图的碎片
│ ? │ ? │ ? │        │ ? │ ? │ ? │
└───┴───┴───┘        └───┴───┴───┘
   开局                拖一步后 → 拼成 2×2 → 消除 +1 组
```
- 缺的那块放在**紧邻缺口**的格（正下 / 正右）：简单模式任意拖、困难模式"挪一格"，两种规则下都**一步合法**；
- 拼成瞬间会有**融合 → 消除 → 下压 → 补位**的完整动画（现有 `playResolution()`），玩家一次看全。

### 5.3 强制拖动 + 滑动演示动画（v3 核心规范）

> 用户要求：**不要文字教学，强制教拖动，只有那一块碎片可以操作，用动画模拟滑动**。
> 这一节把"强制"和"动画"拆成可实现的规则。

#### 5.3.1 输入锁定（怎么做到"只有这块能拖"）

| 规则 | 行为 |
|---|---|
| **只认目标块** | `onPointerDown` 里判断：教学步进行中且按下的不是 `targetIndex` → **直接 return**（不进入拖动态、不响应）。其它块视觉上**压暗**（`opacity: .55` + 去饱和），玩家一眼看出"只有那块是活的" |
| **只认缺口** | 松手时若落点不是 `gapIndex` → **不执行移动**，碎片**弹回原位**（回弹动画 180ms），不做任何提示 |
| **不误伤** | 锁的是"教学步内的操作"，**不锁**：返回键 ✕、跳过教学、音效；演示动画期间玩家一按下就接管 |
| **解锁时机** | S1 完成（消除 1 组）→ **立刻全部解锁**，之后正常玩；S4 同理（拖完那一片即解锁） |
| **兜底** | 若教学步内玩家 30 秒仍未完成 → **降级解锁**（取消锁定），避免卡死；同时不再追着教 |

#### 5.3.2 滑动演示动画（"动画模拟滑动"）

```
   缺口 ⬚ 呼吸虚线框          ① 手指图标落在目标块上（按下态：缩小 + 阴影）
      ↑                       ② 手指沿直线滑向缺口（0.9s，ease-in-out）
   ┌───────┐                  ③ 目标块的**半透明影子**跟着滑进缺口
   │   ◻   │  ← 目标块         ④ 影子落位 → 4 块拼合 → **金色闪光 + 缩放脉冲**（0.3s）
   └───────┘                  ⑤ 影子淡出、手指回到起点（0.4s）→ 循环
```

| 项 | 规格 |
|---|---|
| 周期 | **1.6 秒 / 次**，循环播放（`animation-iteration-count: infinite`） |
| 手指 | 纯 CSS 画（白色圆头 + 描边，或 `👆` 字符放大），**不用新素材**；按下时 `scale(.92)` + 投影 |
| 碎片影子 | 目标块的 `clone`（同一张图、同一位置块），`opacity: .65`，沿 `translate()` 移动 |
| 落位反馈 | 拼合瞬间：缺口框闪金光 + 整图 `scale(1.06)` 脉冲 + 一圈光晕（`box-shadow` 扩散） |
| **玩家一按就停** | `pointerdown` → 立即 `animation: none` 并移除影子，动画不再打扰 |
| **3 秒无操作重播** | 玩家按下又松手没成功 → 3 秒后重新播放 |
| 结束后 | S1 完成后动画**永久移除**（不再出现），手指元素从 DOM 删掉 |

#### 5.3.3 拖错时的反馈（仍然零文字）

| 情况 | 反馈（全部非文字） |
|---|---|
| 按了别的块 | 那块**抖一下**（`translateX` 小幅 2 次，160ms）+ 目标块 **脉冲高亮**（呼吸加强 1 次）→ 视线自然被拉回目标块 |
| 拖到缺口以外 | 碎片**弹回原位**（180ms `cubic-bezier`），缺口框**闪一下**提示"要放这儿" |
| 拼合成功 | 融合 → 消除 → 下压 → 补位 全套动画（现有 `playResolution()`）+ 得分翻牌 +1 |

#### 5.3.4 实现落到哪（预计）

| 位置 | 改动 |
|---|---|
| `web/ui/tutorial.ts` | 新增 `tutorialTarget()`：算出 `targetIndex`（缺的那块）与 `gapIndex`（缺口），以及 `buildTutorialGrid()` 摆放时把这两个位置定下来 |
| `web/ui/tutorial.ts` | 新增 `createHandHint()`：手指 + 影子 + 闪光循环动画组件（`play()` / `stop()` / `dispose()`） |
| `web/main.ts` | `onPointerDown`：教学步内非目标块 → `return`；`onSwap` 前：落点非缺口 → 回弹不结算 |
| `web/ui.css` | `.cell.dim`（压暗）、`.cell.shake`（抖动）、`.tut-hand` / `.tut-ghost`（手指与影子）、`@keyframes` 三套 |
| `web/ui/text.ts` | **删掉** `step1 / step2 / star1 / star2 / step4 / nightmareRule` 等教学文案（v3 不用了）；保留抽屉说明与完成弹窗 |

> ⚠️ **自检修正（2026-10-26）**：现有 HUD **没有星级元素** —— `updateHud()` 只更新计时器与 2 位分数翻牌，`updateGoal()` 只显示 1★ 所需组数（`star1`）。所以"点亮 HUD 星星"不成立，改为：**棋盘上方轻横幅（2 秒淡出、非弹窗）+ 目标区数字递减**，改动小且不打断。若一定要星星 UI，则需新增 HUD 星位（成本更高）。

### 5.2 困难序章（4 步）

| 步 | 教什么 | 文案 | 视觉 / 强制 | 完成判定 |
|---|---|---|---|---|
| **D1** | 规则差异（挪一格） | ⛔ **无** | 目标块与缺口相邻，滑动动画**只走一格**（演示距离本身就说明了"只能挪一格"）；拖远了就回弹 | 一次成功移动 |
| **D2** | 拖动（3 缺 1，与 S1 同盘面） | ⛔ **无** | 同 S1：演示动画 + 输入锁定 | 消除 1 组 |
| **D3** | 目标旗（强制看） | ⛔ **无** | 聚光灯挖出 `#hud-goal`，数字跳变 | 自动关闭 |
| **D4** | 完成 | 完成弹窗 | 弹窗（§6） | 累计 3 组 |

> 困难序章**不重复讲时间**（S3 已在简单序章讲过），省一步；
> 若玩家是直接从抽屉进困难序章（理论上门槛挡住了，仍兜底），则补一步时间说明。

## 6. 星级与完成结算

- 序章星线（教学专用，**写死**，不走 `LEVEL_STAR_LINES`）：

## 8. 序章关卡配置（固定，不随机）

| 项 | 值 | 理由 |
|---|---|---|
| 网格 | `4×3`（12 格） | 与第 1~15 关一致，格子最大（117px），看得清 |
| 图池 | **固定 6 张图 = 6 只动物各 1 张「开心」**（猫0/虎6/兔7/仓鼠8/狗9/熊10） | 每只动物只出 1 张（ma=1），辨识难度压到最低 |
| 初始盘面 | ⭐ **手工构造「3 缺 1」**（`buildTutorialGrid()`，不走随机） | v2 核心：开局就摆好"3 块成 L + 缺的 1 块在旁边"，玩家**拖一步就成**（见 §8.1） |
| 交换规则 | 简单序章 `any` / 困难序章 `adjacent` | 与两个模式正式关一致 |
| 时长 | 180 秒（显示，不走） | 复用正式关 HUD |
| 星线 | `[1, 2, 3]` | 教学专用 |

> 「同关同动物最多 3 张」的 `ma` 约束是**图**的张数上限；序章每只动物 1 张图（4 块），不受影响。

> ⚠️ **实现踩坑（2026-10-26 实测）**：原本写的是「固定 3 图 × 4 块 = 12 块铺满」，但引擎初始化
> （`assignPools`）按 `imagesPerLevel(格数)` = `(12−8)/2+4 = 6` **校验图数**，给 3 张直接抛
> `本关图数不足，需要 6 张，实际 3 张`。所以序章必须是 **6 张图**（24 块的池），场上 12 块从中随机取 ——
> 「某张图的 4 块一定都在场上」这个前提**不成立**（随机盘面下可能只有 2~3 块在场），
> 这正是 v2 必须**手工摆盘**的原因：靠随机撞不出"3 缺 1"。

### 8.1 「3 缺 1」盘面怎么摆（v2 新增，新增 core 函数 `buildTutorialGrid()`）

**放在哪**：`assets/scripts/核心/init.ts` 新增导出（与 `buildInitialGrid()` 并列，不动现有函数）。

**做法**（4 步，全部复用现有能力，不改任何规则代码）：

```ts
export function buildTutorialGrid(rows, cols, imageIds, rng): Grid {
  // ① 照常分池：拿到「哪张图 4 块全在场」= assign.complete
  const assign = assignPools(rows * cols, imageIds, rng);
  // ② 照常生成在场碎片集合（数量 = 格数 = 12），池快照与正式关完全一致
  const pieces = allPiecesForAssignment(assign, rng);
  // ③ 手工摆放：把 complete 那张图的 4 块摆成「3 块成 L + 缺的 1 块在紧邻格」
  //    其余格用剩下 8 块随机填（rng.shuffle）
  // ④ 校验 validateBoard()：内容完整恰好 1 组、位置拼合 0 组 → 不通过就退回 buildInitialGrid()
}
```

**为什么这样是合法的**（已逐条核对代码）：

| 检查项 | 依据 | 结论 |
|---|---|---|
| 图数 | `assignPools` 要求 6 张（12 格） | ✅ 序章给 6 张 |
| 池子结构 | `invariantIssues()` 要求：池子5=1张(4块在场)、池子1=1张(3块)、池子2=`(格数-8)/2`张(各2块)、池子3=1张(1块)、池子4=1张(0块) | ✅ **手工摆放只改位置、不改各图在场块数**，池快照与随机盘面完全一致 |
| 内容完整性 | `validateBoard().content` 必须**恰好 1 组**（HC-01） | ✅ complete 那张图 4 块全在场 = 那 1 组 |
| 位置拼合 | `validateBoard().positionCorrect` 必须 **0 组** | ✅ 3 块成 L 不等于拼成 2×2，不算完成；⚠️ 摆放后必须跑一次校验，不通过就退回随机盘面 |
| 补位 | `refillGrid(grid, config.imageIds, rng)` **只依赖 `cfg.imageIds`**，与 `assignPools` 无关 | ✅ 消除后的补位不受手工摆放影响 |

**摆在哪个位置**（4×3 棋盘，行 0~3 / 列 0~2）：
- 目标 2×2 区取 **行 1~2 × 列 0~1**（棋盘中部偏上，不在最边上，手指好按）；
- 3 块按**正确相对位置**放：左上 `(1,0)`、右下之外的三格 → 缺口取 **`(2,1)`**（右下角）；
- 缺的那一块放在 **`(3,1)`**（缺口正下方，贴着、一步可拖到；困难模式"挪一格"也合法）。

### 9.2 聚光灯 Spotlight（v2 新增组件，`web/ui/spotlight.ts`）

> 用途：讲**目标旗 / 倒计时**这类 HUD 元素时，**把玩家的视线强制拉过去** —— 只留那一个元素亮着，其余全暗，必须点了才继续。

- **结构**：
  ```
  <div class="spot">            ← 全屏容器 z=90（只吃自己这层）
    <div class="spot-hole">     ← 挖洞层：box-shadow: 0 0 0 9999px rgba(0,0,0,.72)
    <div class="spot-next">    ← v3：**零文字**，只有一个向下/向上的「▾ 继续」箭头（点它或点洞内关闭）
  ```
  > v2 的「说明气泡 + 知道了」**已按用户要求去掉**（不要文字教学）；
  > 若某一步确实必须保留一句说明（例如设置页里回看的静态图解），气泡仍可复用，但序章内一律不用。
- **挖洞实现**：一个**绝对定位的圆角矩形**（比目标元素外扩 12px）+ `box-shadow: 0 0 0 9999px rgba(0,0,0,.72)` 把四周压暗；洞内元素**原样亮着**（不复制 DOM，避免和 HUD 的数值刷新脱节）。
- **定位**：`getBoundingClientRect()` 取目标元素屏幕坐标；因为 `#stage` 有 `transform: scale()`，坐标要用**屏幕系**（`getBoundingClientRect` 本身就是屏幕系，无需换算）。
- **指向箭头**：气泡与洞之间画一根 8px 金色箭头（CSS 三角），方向按气泡在洞的上/下自动翻。
- **强制确认**：`知道了` 按钮 / 点洞内区域 → 关闭；**点暗区不关闭**（防止误触跳过）。
- **可讲的目标**（都用现有 id，不用改 HTML）：

  | 目标 | 元素 | 用在 |
  |---|---|---|
  | 目标旗 | `#hud-goal`（旗杆+三角旗 SVG + `#hud-goal-num`） | S2 / D3 |
  | 倒计时 | `#hud-timer`（🕒 + `#hud-timer-num`） | S3 |
  | 得分（可选） | `#hud-score`（翻牌两位数面板） | 首次消除后补一句"这里 +1" |
  | 棋盘缺口（可选） | 目标格 `.cell` | S1 无操作时重播 |

- ⚠️ 与抽屉/弹窗的层级：抽屉 z=80、弹窗 z=?、**聚光灯 z=90（最高）**；同一时刻只允许一个聚光灯。

1. **序章若做成 `level 0`**，`save.ts` 的关卡号校验是 `intIn(raw.level, 1, totalLevels)` —— 序章**不落 session** 即可绕开（已在 §3 排除断点）。

7. **困难通关计数口径**：建议 `Object.values(progressByMode.nightmare.levels).filter(r => r.stars > 0).length >= 10`，与 `totalStars()` 同源，别另算一套。

### 20.1 两套流程（不再共用一套）

| | 简单序章（normal） | 困难序章（nightmare） |
|---|---|---|
| 第 1 步 | 拖动：按住这块碎片，拖到缺口上 | **规则差异**：困难模式，一次只能挪一格 → 接着「挪一格，把这块补进缺口」 |

| 第 4 步 | **整片拖拉**：拼好的整片会一起走，拖一下试试（场上无成片则跳过） | ⛔ 没有 |

  困难没有 `time` / `group`，简单没有 `rule`）；
- 抽屉补充卡也加了一行「🔒 困难模式：一次只能挪一格（教学也会单独讲这一条）」，让玩家在点开抽屉时就看到差异。

### 20.2 简短文本的规格

- **≤ 16 字、一句一个信息点**：既是屏幕上那一行（长了要换行、挡棋盘），也是要念出来的话（TTS 念长句像念稿）；
- **显示位置**：棋盘上方轻横幅（`.tut-banner`）；聚光灯步骤用贴着洞的**气泡**（`.spot-tip`，自动上/下避让）；
- **显示时长要盖住朗读**：`1200 + 字数 × 190` ms —— 否则会出现"声音还在念、字已经没了"。

### 20.3 语音怎么做（`web/ui/speech.ts`）

用浏览器自带 **Web Speech API（`speechSynthesis`）** 朗读中文：

| 决策 | 理由 |
|---|---|
| **TTS 而不是音频文件** | `art/` 里没有任何音频素材，录配音要等资源；TTS **零素材、零包体**（微信小游戏包体是硬约束），文案改了不用重录 |
| **将来接真配音只换本文件** | 与 `audio.ts`（占位合成音）同一套路：`speak()` 换成 `<audio>` 播放即可，调用方一行不动 |
| **不支持就彻底静默** | 没有 `speechSynthesis` / 没有中文语音时 `speak()` 是空操作 —— **教学不能因为语音不可用而卡住**，文本照常显示 |
| **首次手势里预热** | iOS/Safari 不在真实手势里首次 `speak`，之后永远不出声；`warmup()` 挂在 main.ts 首次 pointerdown（与 `audio.unlock()` 一起），用 `volume = 0` 的空句只拿许可不出声 |
| **说下一句先 cancel** | 教学是一步一步的，两句叠着念反而听不清 |
| **独立开关「教学语音」** | 存 `meta.settings.voice`（老档默认开）；关掉后**只显示不念**。与「音效」分开：有人想听讲解不要音效，也有人相反 |

## 22. v4.1-b：摆盘与推进的三个修正（2026-10-26，试玩反馈）

> 用户：**"根本没停 5 秒啊，最后，倒计时走完那句。教学碎片图不要放相邻位置。
> 困难关教学可以多走几步。简单关直接远距拖动"**

| # | 反馈 | 原因 | 改法 |
|---|---|---|---|
| 1 | **「倒计时走完」那句没停 5 秒** | `tutorialStepTime()` 是 show 完**立刻**开始走 3 秒倒计时、走完就 `hide()` —— 那句话总共只停了 3 秒 | **先留 5 秒**把这句话读完听完，**再**走 3 秒（期间气泡继续挂着不 hide）。实测：倒计时在 **5476ms** 才开始动 |
| 2 | **教学碎片不要放相邻位置** | `buildTutorialGrid()` 把缺块**固定**摆在缺口正下方（`gapIndex + cols`），紧挨着 | 改为按规则算落点：简单 = **离缺口最远**、困难 = **最短路 2 步**（都不相邻） |
| 3 | **困难教学多走几步 / 简单直接远距拖** | 两套都是"一步到位"，困难没体现"一次只能挪一格" | 简单：一次**远距**拖到缺口（落点仍必须是缺口）；困难：**每步挪一格、走两步**，中途提示「继续往缺口挪一格」 |

### 22.1 摆盘：核心侧按规则选位置（`init.ts`）

```
从缺口做 BFS（绕开已拼好的 3 块）→ 得到每格「最少要挪几步」
  简单 any      → 取**最远**的那一格（实测 index 0，距离 3）
  困难 adjacent → 取**≥2 步里最近**的（实测 index 5，距离 2 → 走两步）
```

- `TutorialLayout` 新增 `fixed: number[]`（已拼好的 3 块）—— 找路要绕开，也防止玩家把它们拖散。
- 兜底不变：摆不出来 / `validateBoard()` 不过 → 返回 `null`，教学降级为不锁定输入。

### 22.2 困难：一步一步带着走

- **落点锁**：困难下必须落到「手指演示的那一格」（朝缺口更近的相邻格），**不许往别处绕** ——
  否则玩家能把缺块越拖越远，教学就散了；
- **手指演示**改指**下一步**那一格（不是直接指缺口）：一次只能挪一格，演示一个够不着的落点会让人按不出来；
- **每挪一步**提醒一句「继续往缺口挪一格」，到缺口才消除。

### 22.3 踩坑：标记被动画冲掉（已修）

`marks` 在困难第一步之后**全没了**：`tutorialAfterMove()` 是在移动动画**播放之前**调用的，
随后「消除 → 下压 → 补位」会重排棋盘，把刚加的 `.pulse / .gap / .dim` 冲掉。
**改法**：说话留在 `tutorialAfterMove()`，重摆视觉挪到动画播完的 `tutorialAfterResolve()` 里。
