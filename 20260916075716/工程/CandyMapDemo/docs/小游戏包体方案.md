## 二、已落地的工具链

### 1. 图片压缩 `tools/minify-assets.mjs`

依赖 ffmpeg（含 libwebp）。实测数据（本机）：

| 组 | 处理 | 实测结果 |
|---|---|---|
| 贴纸 | WebP q82，保留 512 宽（图鉴有大图预览，不能缩太狠） | 待跑实测 |
| 世界底图 | 1080 宽不降分辨率：q76 → **7.60 MB**；q70 → **6.71 MB** | 已配 q76 |
| 世界底图（备选） | 降到 810 宽 q72 → **4.15 MB** | 需要塞进单个分包（≤4 MB）时再改 `vf` |
| 界面切图 | WebP q80 | PNG 2.48 MB → **0.17 MB**（扁平色 + 大面积透明，压缩率极高） |

顺带修了一个 bug：贴纸组原来递归整个 `assets/resources`（把 `map/`、`ui/` 也卷进去，
输出同名且难用的路径），已收窄为 `assets/resources/stickers`。

### 2. 字体子集化 `tools/gen-font-chars.ps1` + `tools/font-chars.txt`

- 扫描 `assets/scripts` 里**真正会显示**的字符，实测 **1218 个**（含汉字、符号、emoji）
- 输出 `font-chars.txt`，UTF-8 **无 BOM**（首字节 `EF B8 8F`，pyftsubset 只认 UTF-8）
- ASCII（`U+0020-007E`，数字/比分/`x1.5` 等）由 `pyftsubset --unicodes=U+0020-007E` 单独指定

```bash
# 子集化命令（需 fonttools）
pyftsubset HarmonyOS_Sans_SC_Medium.ttf \
  --text-file=tools/font-chars.txt \
  --unicodes=U+0020-007E \
  --output-file=assets/resources/font/HarmonyOS_Sans_SC_Medium.subset.ttf
```

⚠️ 16 MB → 子集化后预计几百 KB，但**未实测**（本机 fonttools 未确认）。若没有 fonttools，
降级方案是**远程加载字体**（项目永久指令允许：字体不得顶穿主包）。

## 三、分包方案（Cocos Creator 3.x）

工程判定为 **Creator 3.x**：`settings/v2/` 目录结构 + `.meta` 为
`{"ver":"1.1.60","importer":"scene",...}` 格式（2.x 的 meta 与目录结构不同）。

分层目标：

| 层 | 内容 | 预估体积 |
|---|---|---:|
| **主包** | UI 切图（压缩后）+ layout + 字体子集 + 第 1 世界底图（压缩后）+ 节点珠 | **< 2 MB** |
| **分包 A** | 其余 14 张世界底图（压缩后） | ~7 MB |
| **分包 B** | 108 张贴纸（压缩后） | 待实测 |

做法（Creator 3.x）：把 `map/`、`stickers/` 配成 **Asset Bundle**（目录 `.meta` 里
`isBundle: true`），再在构建面板把 bundle 的压缩类型设为**小游戏分包**；
或直接在 `game.json` 配 `subpackages`。

### ⚠️ 配套的代码改造点（未完成，需后续会话执行）

把资源移出 `resources` 后，`resources.load` 的路径语义会变，必须同步改：

1. `assets/scripts/场景/worlds.ts` → `worldArtPath()` 现返回 `map/wN_xxx`
   （供 `resources.load('map/w1_town', SpriteFrame)` 用）
2. `assets/scripts/场景/MapBootstrap.ts` → `createMapBackground()` 的
   `makeSprite(..., 'map/wN_xxx', ...)` 与 `switchWorld()` 换世界时的加载，
   需改为 `assetManager.loadBundle('map')` 异步加载，并处理「分包未下载完」的兜底
   （首次切世界可能要等下载，应给加载态提示）
3. `assets/scripts/界面/CollectionScreen.ts` → 贴纸 `stickers/sticker_N/spriteFrame`
   同理；图鉴是滚动列表，建议**按可视范围懒加载**（108 张全量加载会卡）

这三处改完才算真正落地，否则只是把图挪了个位置。

## 四、人工验证清单（需在装了 Creator 的机器上做）

1. 打开工程 → **构建面板** → 发布平台选 **微信小游戏** → 构建
2. 查看构建产物主包体积（目标 **< 4 MB**，留余量）
3. 确认分包配置生效：产物里应有独立的分包目录
4. 微信开发者工具打开 → **「本地设置」勾选「校验域名」关闭**（本地调试）→ 编译
5. 真机验证：
   - 进首页看到第 1 世界底图（主包内，应秒出）
   - 切到第 2 世界：确认触发分包下载且**有加载提示**，下载完成后底图正常显示
   - 进图鉴：确认贴纸分包按需加载，滚动不卡
   - 结算吊牌、排行榜页字体正常（子集化没丢字）
6. 若主包仍超 4 MB，按顺序砍：底图降到 810 宽（→4.15 MB）→ 贴纸降分辨率 → 字体改远程加载
