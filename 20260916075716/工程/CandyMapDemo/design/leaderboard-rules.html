排行榜规则方案（产品原型）

2026-10-25 · 左边手机按本页规则实时计算；在下面「沙盘」里改成绩，榜单 / 我的成绩 / 上榜状态 / 荣誉档位会跟着变。

一、现状评估（读代码得出的问题）

位置现在怎么算问题
总分榜·我的总分两种模式所有关卡「个人最高分」相加，含续命局口径冲突 关卡榜不收续命局，总榜却收；续命 +60 秒可直接刷总分
总分榜·别人100 个模拟玩家，总分 380~980 随机量级不对 实际 1 关只有 5~15 分，60 关满打也就 ~600；新玩家永远垫底，看着像假榜
总分榜·名次排序后直接 1、2、3… 编号并列不一致 关卡榜同分同名次（1,1,3），总榜不并列
关卡榜≥3★ 且未续命才上榜，按本关上榜最高分排规则合理；但模拟玩家全部 ≥3★ 线，真实玩家的榜单还没接
荣誉档位超神 = 名次 ≤100 且总人数 >100；王者 = 超越 ≥90%数学问题 101 人时上榜≈必得超神；总人数 <1001 时王者不可能出现（代码注释里已记录）
服务端 /rank/global只收简单模式上报；总分 = 各关最高分和；排序 总分↓ 总星↓两边对不上 客户端总榜算两种模式，服务端只算简单；续命局分数也照收
好友榜（微信 KV）两模式总分 + 总星和服务端口径又不同；三个榜三套数

二、新规则（建议）

1. 三个数字的定义 —— 全部只认「有效成绩」

名词定义
有效成绩没有续命、且至少拿到 1★ 的一局。续命局照常通关、照常解锁下一关、照常记个人最高分（自己看），但不进任何排行。
关卡分某关某模式的「有效成绩最高分」。
总积分Σ 简单关卡分 + Σ 困难关卡分 × 1.5（向下取整）。困难加权：困难要先三星简单才能开、规则更难，给 1.5 倍让它值得打。
总星数Σ 每关每模式的最高星级。上限 60 关 × 3★ × 2 模式 = 360★；续命局按规则记 1★，可以计入（星数是收集进度，不是竞技分）。

2. 上榜条件

榜上榜条件排序（同上则并列同名次）
总榜总积分 > 0（至少有一局有效成绩）总积分↓ → 总星数↓ → 先达到者优先
关卡榜本关本模式有≥3★ 的有效成绩（沿用策划《通关及排名》）关卡分↓ → 先达到者优先
好友榜总积分 > 0与总榜同口径（微信 KV 写同一套数）

名次统一用「竞赛排名」：同分同名次、下一名跳号（1, 1, 3）。榜单只展示前 100 名（含并列）；没进前 100 的，「我的成绩」里显示真实名次或「100+」，并给出距上一名 / 距上榜还差多少 —— 这是让玩家再来一局的钩子。

3. 荣誉档位（结算弹窗）—— 改成按百分比，人少人多都成立

档位条件（本关本模式，有效成绩 ≥3★ 才评）
超神 👑名次在前 1%，或名次 ≤ 10（人少时保底）
王者 🏆名次在前 10%
优秀 ⭐其余通关（含 1★ / 2★ / 续命局）

4. 数据来源与「示例数据」

服务端为准 登录后榜单全部来自服务端；离线 / 未登录时显示本机成绩 + 示例对手，并在榜底标明「示例数据，联网后显示真实排名」，不再冒充真榜。示例对手的分数按真实星线生成（每关 3★ 线上下浮动），量级与真实玩家一致。

5. 需要服务端配合的改动

接口改动
POST /game/api/level/result新增 mode（normal/nightmare）、revived；困难不再按关号偏移上报（现在被关卡守卫拒）；续命局只更新进度与星数，不更新关卡分
game_progress拆 score_normal / score_hard / total_score(加权) / total_stars / reach_time，排行索引 (total_score, total_stars, reach_time)
GET /game/api/rank/global按新排序，返回 rank（竞赛排名）、nickname、avatar、score_normal、score_hard、total、stars
GET /game/api/rank/level?level=&mode=新增 关卡榜前 100 + 我的名次、总人数（荣誉档位用）
GET /game/api/rank/me补「距上一名还差多少分」
