## 0. 一句话摘要

每张表情包产出 **1 张 512×512 完整图**；该图按 **2×2 四等分**得到 **4 张 256×256 碎片**。
碎片必须**无缝、无白边、无描边、无圆角**，4 块拼回后与原图**逐像素完全一致**。

## 2. 核心尺寸与切分规范

### 2.1 切分示意

```
          sticker_X.png  （完整图，512×512）
   ┌────────────────┬────────────────┐
   │   碎片 0       │   碎片 1       │
   │   左上         │   右上         │
   │ (0, 0)         │ (256, 0)       │
   ├────────────────┼────────────────┤
   │   碎片 2       │   碎片 3       │
   │   左下         │   右下         │
   │ (0, 256)       │ (256, 256)     │
   └────────────────┴────────────────┘
                  ↓ 四等分
   fragment_X_0.png   fragment_X_1.png
   fragment_X_2.png   fragment_X_3.png   （各 256×256）
```

### 2.2 切分坐标表（严格按此执行）

| 碎片序号 | 位置 | 像素区域（左上原点，x:y:宽×高） |
|---|---|---|
| 0 | 左上 | `0:0:256×256` |
| 1 | 右上 | `256:0:256×256` |
| 2 | 左下 | `0:256:256×256` |
| 3 | 右下 | `256:256:256×256` |

> 坐标系：**以图像左上角为原点**，x 向右、y 向下。
> 与策划案 §3.3「碎片 ID ÷ 4 的余数 = 位置（0左上/1右上/2左下/3右下）」完全对应。

### 2.3 切图方式（二选一，由项目负责人拍板）

| 方案 | 做法 | 交付物 | 说明 |
|---|---|---|---|
| **A. 预切文件** | 美术或脚本把 512×512 切成 4 个 256×256 文件 | `sticker_X.png` + `fragment_X_0~3.png` | 直观，与策划案附录A 命名一致；但资源数 ×4 |
| **B. 不切文件** | 只交付 `sticker_X.png`，引擎按 UV/rect 取 1/4 显示 | 仅 `sticker_X.png` | **推荐**：资源数少 4 倍、包体更小；Cocos Creator 用 Auto Atlas + Sprite rect，Unity 用 Sprite Mode=Multiple |

**结论：采用哪个方案不影响美术的绘制要求**——两种方案都要求原图 512×512、四等分后无缝。
方案 A 的切图工作**不建议美术手工做**，由程序脚本或引擎导入时自动完成（见 §7.2）。

## 4. 绘制红线（MUST / MUST NOT）

### 4.1 MUST

1. 画布**正好 512×512**，不多不少（非 512 直接拒收）
2. 四等分后每块**正好 256×256**
3. 切缝处**像素连续**，拼回原图无接缝、无色差、无错位
4. 碎片**无透明边距**（策划案 §11.6.1）
5. 交付 **PNG-24**（不要 JPG：压缩噪点会导致逐像素比对失败）
6. 4 块碎片**拼回后与原图逐像素一致**（策划案 §11.6.3）

### 4.2 MUST NOT

| 禁止项 | 原因 |
|---|---|
| ❌ 留安全边距 / 白边 / 外框 | 切完拼不回，出现缝隙；会导致 §11.6.3 验收失败 |
| ❌ 加圆角 | 碎片四角会被切掉，网格中拼不出完整图 |
| ❌ 加外阴影 / 发光 | 阴影落在画布外会丢失，落在画布内则与相邻碎片接不上 |
| ❌ 加水印 / 签名 / 文字 | 会出现在游戏画面里；文字还可能涉及字体版权 |
| ❌ 后期整体缩放（非整数倍） | 出现半像素模糊，逐像素比对必失败 |
| ❌ 在图像内画"碎片边框" | 拼合时会出现网格线，破坏"像一张完整图"的核心体验（策划案 §11.6） |
| ❌ 纯白 / 纯色大面积背景 | 玩法致命伤，见 §5.2 |

## 5. 玩法驱动的可辨识性要求（美术必须理解）

> 这一章是本项目美术最容易踩的坑，**不是审美问题，是玩法问题**。

> **⚠️ 优先级（v1.2 确立）：情绪可读性 > 碎片可辨识性 > 画面好看。**
> 三者冲突时永远往上让。详见 §5.5。

### 5.1 玩家要做什么

玩家在网格里看到的是**一堆打散的碎片**，需要判断"哪 4 块属于同一张图"，然后交换位置拼成 2×2 才能消除。
如果 4 块碎片长得都差不多，玩家只能靠穷举试错 → **关卡从"眼力游戏"退化成"运气游戏"**。
反过来，如果拼出来的图看不出是什么情绪，图鉴/收集的意义也就没了 → **情绪必须一眼读懂**。

### 5.2 因此硬性要求

1. **同一张图的 4 块碎片必须有明显差异**
   - 主体特征（五官、肢体、色块）要**分散到 4 个象限**
   - 避免整图大面积单色、纯白底、中心一团、四角留白
   - 注意：一张图切开后，**边缘的 2~3 块碎片大部分面积是背景 + 道具**，所以差异不能只靠脸
2. **必须用 5 层信息叠加来制造差异**

   | 层次 | 内容 | 覆盖范围 | 由什么决定 |
   |---|---|---|---|
   | ① 姿态 / 动作 | 跳跃、后仰、擦眼泪、叉腰、伸爪 | 决定主体轮廓分布 | 情绪 |
   | ② 情绪道具 | 星星、雨滴、火苗、闪电、皇冠、爱心 | 主体两侧 | 情绪 |
   | ③ 招牌道具 | 动物专属物件（毛线球、胡萝卜、坚果…） | 主体两侧 | 动物 |
   | ④ 背景纹理图案 | 光芒线、细雨线、斜条纹、波纹、光晕、波点 | **铺满画面，边缘碎片的主力** | 情绪 |
   | ⑤ 表情 | 眼 / 嘴 / 眉须耳 | 仅中心碎片可见 | 情绪 |

   > **情绪是唯一驱动维度**：姿态、情绪道具、背景纹理、色调、表情全部跟情绪走（1:1 绑定）；
   > 动物只决定"长什么样"（物种 + 毛色）。招牌道具是次级装饰，**与情绪表达冲突时一律删掉**。

3. **比例要求（v1.2 修正）**
   - **必须用 Q 版大头比例**，这是"脸够大、情绪读得出"的前提：

   | 项目 | 数值 |
   |---|---|
   | 头身比 | 约 **1:1.5**（头大身小的 Q 版） |
   | 头部（含耳朵）占画面高度 | **30%~35%** |
   | 全身合计占画面高度 | **70%~80%** |
   | 五官位置 | 集中在头部下半部 |

   > v1.1 只写"全身占 70%"，AI 会按写实比例画 → 头只占 15% → 缩到 60px 后眼睛糊成一团，情绪读不出。
4. **姿态要求（v1.2 修正：姿态必须服务于情绪）**
   - 姿态必须**舒展、有动作**：四肢张开、有明确的动作方向
   - 姿态本身要能表达情绪（跳跃=开心、炸毛跺脚=生气、后仰=惊讶、挺胸叉腰=得意、低头擦泪=难过、挡脸侧身=害羞）
   - 道具至少 2 个，**分散在画面左右两侧**，不要挤在同一处

   | ❌ 禁止 | 原因 |
   |---|---|
   | 背对镜头 | 整幅是同一片背色 → 4 块碎片趋同，且完全读不出情绪 |
   | 蜷缩成一团 / 抱成一球 | 同上，一个大色块 |
   | 大面积侧躺露背 | 躯干占 2~3 个象限且颜色单一 |
   | 主体过小（<50% 画面） | 退化为"边缘碎片全是背景" |
   | **爪子 / 道具挡住眼睛或嘴** | **情绪读不出（破坏最高优先级）** |
   | **捂脸捂到整张脸被遮** | 同上；害羞只能是"**挡半边脸颊，眼睛可见**" |
5. **背景不得抢戏（v1.2 新增）**
   - 背景图案的**明度比主体略高、对比比主体略低**
   - 主体靠**粗黑描边**从背景中跳出
   - 背景不得遮挡五官所在一带
6. **同一关内的图之间要有强区分**
   - 同一关可能同时使用 6~12 张图（策划案 §5.2）
   - 建议每张图有**一个主色相**，且同关内不重复（如：橘猫 / 蓝猫 / 绿蜥蜴 / 粉兔…）
   - 避免"一只白猫的 8 种表情"整关同屏
   - ⚠️ 已知风险：策划案附录B.1 的**关卡 1~6 用的正是图 0~5（全猫）**，同动物之间的区分必须靠姿态 + 背景纹理 + 招牌道具拉满
7. **小尺寸可辨识**
   - 手机上单块碎片的实际显示尺寸约 **55~90 px**（3×4 网格 4 列 ≈ 90px；4×6 网格 6 列 ≈ 55px，以 360pt 屏宽估算）
   - 验收时请把成品**缩到 60px 目视检查**，看不清细节就重画
   - 判据：缩小后 ① 仍能看出"这块属于哪张图" ② 仍能读出情绪

### 5.3 建议做法

- 每张图给一个**高饱和主色 + 高对比明暗**，别用低对比度配色
- 背景必须是**图案明显、面积大、颜色明确**的纹理，**不得虚化、不得大面积纯色、不得淡雅渐变**——它是边缘碎片的主要区分依据
- 表情的"情绪信号"（眼睛、嘴、眼泪、爱心等）尽量靠近画面中心区域附近，保证至少 2 块碎片能看出来
- 姿态优先选**四肢张开、有道具介入**的动作（跳跃 / 扑蝶 / 爬树 / 玩毛线球 / 后仰），它天然把特征分散到各个象限
- 边框/外轮廓线可以画，但必须是**图像内容的一部分**，不能是"画布外框"
- 详细的姿态、表情、情绪道具、动物招牌道具对照表见 `AI生图Prompt清单_V1.2.md` §1.3 / §1.4

### 5.4 缩略图（可选交付）

图鉴是 3 列网格展示（策划案 §11.3），512×512 直接当缩略图略耗性能。
建议额外交付 `sticker_X_thumb.png`（128×128），若程序侧用引擎自动降采样，则本项可省。

### 5.5 情绪可读性（**v1.2 新增 · 最高优先级**）

> 这一节的要求**高于** §5.2 的所有内容。若为了碎片区分度而牺牲了情绪辨识，视为不合格。

#### 5.5.1 情绪识别的三层信号

| 优先级 | 信号 | 说明 |
|---|---|---|
| 第 1 | **脸**（眼睛 + 嘴 + 眉须耳） | 情绪识别的主要依据，必须清晰、放大、不被遮挡 |
| 第 2 | **姿态 / 动作** | 全身轮廓独立传达情绪 |
| 第 3 | 道具 + 背景 + 色调 | 氛围强化 |

#### 5.5.2 脸部特征对照表（按此绘制）

| 情绪 | 眼睛 | 嘴 | 眉 / 胡须 / 耳 | 附加信号 |
|---|---|---|---|---|
| 开心 | 眯成弯月形笑眼，眼尾上扬 | 大张嘴笑，可露小舌头 | 胡须上扬、双耳立起 | 腮红、脸颊高光 |
| 难过 | 下垂八字眼，眼中含泪 | 嘴角向下撇 | 胡须下垂、**双耳耷拉** | **一滴眼泪滑落**、头顶小乌云 |
| 生气 | 瞪成倒八字，露眼白 | 龇牙咧嘴 / 咬牙 | 眉毛下压、**胡须向外竖起** | 头顶蒸汽、怒气符号 |
| 惊讶 | 圆圆瞪大，瞳孔缩小 | **O 型小圆嘴** | 眉毛高挑、双耳竖直 | 头顶惊叹号、小汗滴 |
| 得意 | **半眯斜视** | **单侧上扬的坏笑** | 单侧眉毛挑高、一侧胡须翘起 | 下巴上扬、闪光 |
| 害羞 | 向下看 / 眯成一条缝 | 小小抿嘴笑 | 耳朵向内扣 | **大面积腮红**、爱心 |

#### 5.5.3 易混情绪识别对（**重点验收项**）

| 易混对 | 为什么容易混 | 区分关键 |
|---|---|---|
| **开心 ↔ 得意** | 都是正向情绪 + 亮色调 + 闪光元素 | 开心=**弯月笑眼 + 张嘴大笑 + 身体跃起**；得意=**半眯斜视 + 单侧坏笑 + 端坐挺胸仰头** |
| **难过 ↔ 害羞** | 都低头、都不笑 | 难过=**眼泪滑落 + 耳朵下垂**；害羞=**大面积腮红 + 抿嘴 + 挡脸** |
| **惊讶 ↔ 生气** | 都瞪眼、都是高压情绪 | 惊讶=**O 型嘴 + 后仰 + 瞳孔缩小**；生气=**龇牙 + 前倾跺脚 + 胡须竖起** |

验收方式：**把这三对图并排、缩到 60px，看能否立刻说出是哪个情绪**。说不出即判不合格。

#### 5.5.4 「每块碎片都能读出情绪」的分层布置

| 区域 | 承担的情绪信号 | 要求 |
|---|---|---|
| 中心象限 | 脸部（眼 / 嘴 / 眉须） | 五官必须落在画面中心 1/3 区域内 |
| 边缘象限 | ① 情绪道具 ② 姿态肢体（举起的爪、翘起的尾、耷拉的耳） | **至少一个情绪道具放在画面边缘象限**；至少一只爪子或尾巴伸到边缘 |
| 全画面 | 背景纹理 + 色调 | 铺满，作为氛围底 |

#### 5.5.5 情绪可读性红线

| ❌ 禁止 | 后果 |
|---|---|
| 爪子 / 道具挡住眼睛或嘴巴 | 情绪无法识别 |
| 捂脸捂到整张脸被遮住 | 同上（害羞只能挡半边脸颊） |
| 五官过小（头部含耳不足画面高度 30%） | 缩到 60px 后表情糊成一团 |
| 表情与情绪不符（如"得意"画成张嘴大笑） | 与图鉴文案/音效不符，玩家困惑 |
| 背景图案压在五官一带 | 干扰情绪识别 |

## 7. 验收标准

### 7.1 逐像素回拼验收（核心项，策划案 §11.6.3）

程序把 `fragment_X_0~3.png` 按 0/1/2/3 顺序拼回 **512×512**，与 `sticker_X.png` **逐像素比对**：

| 检查项 | 通过标准 | 失败处理 |
|---|---|---|
| 拼回尺寸 | 512×512 | 拒收 |
| 逐像素差异 | `diff 像素数 == 0`（完全一致） | 拒收，重新切割 |
| 缝隙 / 描边 / 色差 | 无 | 拒收，重新切割 |

> 若原图本身带圆角、白边、阴影或做过非整数缩放，**切图无法修复**，只能重画。请在批次 0 就验证通过。

### 7.2 程序侧自动校验（由开发实现，交付前必跑）

| 检查 | 标准 |
|---|---|
| 尺寸校验 | 完整图 == 512×512；碎片 == 256×256 |
| 格式校验 | PNG-24；碎片边缘无半透明像素 |
| 数量校验 | 图 ID 0~19 齐全；每图 4 块；无缺号、无多余文件 |
| 命名校验 | 全部小写、符合 §3 规则 |
| 回拼校验 | 见 §7.1 |

### 7.3 人工目视验收

| 项目 | 标准 |
|---|---|
| 小尺寸可读性 | 缩到 60px 仍能分辨属于哪张图（§5.2） |
| 网格内可辨识性 | 同一关图混排后，能快速找出同图 4 块 |
| 无侵权元素 | 无明星、无知名 IP、无品牌 logo（§8） |
| 风格一致性 | 与批次 0 定稿风格一致 |

## 9. 占位图规范（程序开发期使用）

美术未就绪时，程序使用占位图开发，**规格必须与正式素材完全一致**，以便无缝替换：

- 尺寸：严格 512×512 / 256×256
- 命名：与 §3 完全一致
- 内容：**纯色块 + 中央编号文字**，格式 `图ID.碎片序号`（如 `7.2`）
- 颜色：按图 ID 取固定色（可哈希生成），保证同图 4 块同色、不同图不同色
- 目的：验证"4 块同色碎片凑成 2×2 才消除"的逻辑正确性
