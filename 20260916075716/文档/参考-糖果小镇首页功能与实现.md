# 参考：糖果小镇微信小游戏「首页」功能与实现

> 用途：给《萌宠拼拼乐》开发用。糖果小镇（CandyCrushSaga）的小游戏首页已经跑通并上过真机，本文把它**首页有什么、每项怎么做**整理出来，供直接对照实现。
> 源码在本机 `C:\idea-xiao\CandyCrushSaga\universal-map-editor\src\minigame\`（TypeScript，可读可抄）。
> 两个项目首页同构：顶栏（头像/昵称/体力）+ 难度切换 + 中央大地图 + 底部 4 标签导航。萌宠拼拼乐用 Cocos Creator 3.8，渲染层做法不同，但**交互规则、数据模型、体力/云同步协议、微信适配的坑**全部可以照搬。

## 一、技术形态（先知道它是怎么搭的）

- **纯 Canvas 2D，不用 DOM、不用游戏引擎**。微信小游戏包 = `game.js`（vite 把全部 TS 打成单文件）+ `images/`（地图大图）+ `game.json` 等配置。
- **一帧画两层**：底层是地图（世界坐标，带相机），上层是外壳 UI（屏幕坐标 / CSS 像素）。UI 不建节点、不建 DOM，每帧重画。
- **Host 宿主抽象**（`host.ts`）：把「画布 + 触摸 + 存储 + 登录 + HTTP + 键盘输入 + 震动」收敛成一个接口，有两个实现——`wechatHost.ts`（wx.\*，真机/开发者工具）和 `browserHost.ts`（DOM，网页冒烟自测）。同一套入口代码两边都能跑。
- **入口**（`main.ts`）：判断 `wx` 是否存在 → 选宿主 → 建 `CloudSync`（云同步）→ `startGame(...)`。
- 三消玩法不是首页的一部分，通过一个 `openLevelFactory` 接口挂进来（见 §五.9）。

```
┌─────────────────────────────┐
│ ←刘海/胶囊让位 topInset→      │  顶栏：头像+昵称 / 体力 / 难度 / 星数
│ [头像 昵称]        [♥ 5 3:12+]│
│ [普通][困难]        [⭐ 6/36] │
│                             │
│        中央大地图             │  拖动浏览 / 点关卡进入
│   (关卡节点/章节/小人/云)      │
│                             │
│ [首页][排行][图鉴][设置]      │  底部导航（底部让位 bottomInset）
└─────────────────────────────┘
```

## 二、首页功能清单（有什么）

### 顶栏

| 功能 | 交互 | 数据来源 |
|---|---|---|
| 头像 + 昵称（左上） | 点整个头像/昵称条 → 跳设置页改资料 | 本地存 `candy.profile`；登录时同步后端 |
| 体力条（右上） | 点数字 → toast 显示当前体力/上限；点绿色「+」→「购买/恢复体力：敬请期待」（占位） | 体力系统（§四.1），倒计时实时走 |
| 难度切换「普通/困难」 | 点普通即切；困难未解锁时灰显带锁，点了 toast 解锁条件；切困难后 toast「进度单独记录」 | `candy.difficulty` |
| 星数（右侧同一行） | 无交互，纯显示「⭐ 已得星/总星」 | 当前难度的进度算出来 |

### 中央地图

| 功能 | 说明 |
|---|---|
| 拖动浏览 | 相机跟随手指，限制在地图边界内（clamp） |
| 点关卡进入 | 点到关卡节点且已解锁 → 扣体力 → 打开三消；未解锁 → toast「先通过第 N 关」 |
| 关卡节点状态 | 未解锁：压暗+灰关号+小锁；当前关：呼吸光环；已通关：节点下显示星级 |
| 章节叠加 | 每章底边画章名横幅；未解锁章节整片压暗 +「完成第 N 章解锁」 |
| 通关行走动画 | 通关返回地图时，小人从刚打的关走到新解锁的关，镜头跟随（1.2~3 秒，按路程） |
| 云层 | 6 朵半透明云缓慢横移（固定种子，每次一样），跟屏幕不跟地图 |

### 底部导航与外壳

| 功能 | 说明 |
|---|---|
| 4 标签：首页/排行/图鉴/设置 | 选中金黄高亮，未选中灰；点即切页 |
| 非首页页 | 整屏米白底色盖住地图 + 顶部标题条 + 内容区（裁剪）+ 底导航 |
| Toast | 最多 2 条堆叠，2.6 秒淡出，深色圆角条，画在导航上方 |

### 其他三页（首页的延伸，一并给出）

- **排行页**：全服/好友两个子标签。全服走后端接口，前三名金/银/铜徽章，「我的排名」吸底一条；好友榜用微信开放数据域画到 sharedCanvas 再整张贴过来。三态：加载中/空数据/网络失败（可点重试）。
- **设置页**：昵称（行内编辑）、8 个预设头像（emoji 占位）、音效/音乐/震动三个开关、清除缓存（confirm 后清空本地并回到首页）、版本号。
- **图鉴页**：占位「策划中」。

## 三、关键数据模型（可以直接抄）

```ts
// 闯关进度（game/levels.ts）
interface Progress {
  unlocked: number;              // 当前可玩的最大关号
  stars: Record<string, number>; // 关号 → 最好星级 1–3
  best: Record<string, number>;  // 关号 → 最高分
}
interface LevelResult { level: number; win: boolean; stars: number; score: number }

// 玩家资料（settings.ts）
interface Profile { nickname: string; avatar: number }   // avatar = 预设头像下标
interface Settings { sound: boolean; music: boolean; vibrate: boolean }  // 默认全 true

// 体力（stamina.ts）
interface StaminaRule { max: number; recoverMs: number; cost: number }  // 默认 5 / 30分钟 / 1
interface StaminaState { value: number; at: number }  // at = 该值对应的时间戳
```

**本地存储 key 一览**（微信 `wx.setStorageSync`，全字符串 JSON）：

| key | 内容 |
|---|---|
| `candy.settings` / `candy.profile` | 设置 / 昵称头像 |
| `candy.stamina` | `{value, at, pending}`（pending 见 §四.1） |
| `candy.difficulty` | `'normal'` / `'hard'` |
| `ume-game:<mapId>` | 普通模式进度（沿用老 key，升级不丢档） |
| `ume-game:<mapId>.hard` | 困难模式进度（**同一套关卡、两份进度**，key 加后缀区分） |
| `candy.cloud.token` / `candy.cloud.queue` | 登录 token / 离线待补传的结算队列（上限 200 条） |

## 四、每项功能的做法

### 1. 体力系统（`stamina.ts`，150 行纯逻辑 + 单测）

- **规则**：上限 5、每 30 分钟回 1 点、进关扣 1、通关返还 1。
- **双轨**：已登录 → 以后端为准（进关 `POST /stamina/consume`、通关 `POST /stamina/refund`，规则以服务器返回为准）；未登录/请求失败 → 本地按同一套规则计算兜底，**弱网不卡玩家**。
- **纯函数核心**（本地和服务端各实现一份，规则一致）：`recover(state, rule, now)` 按经过时间恢复；`nextInMs` 算下一点倒计时；`consume` 不够扣返回 null；`refund` 封顶补回。
- **pending 计数**：本地模式下记录「已扣未结算」的局数，通关返还必须有对应扣除，防白嫖。
- **倒计时本地化**：服务器只返回 `nextInSec`（距下一点秒数），客户端换算回本地的 `at` 时间戳，之后倒计时本地自己走，不用轮询。
- 首页只显示 `value / nextIn`；进关时先 `tryConsume()`（异步，可能等后端），期间置 `playing` 标志防重复点；失败 toast「体力不足，M:SS 后恢复 1 点」。

### 2. 难度模式（`difficulty.ts`）

- 普通/困难两份进度分开存（key 加 `.hard` 后缀），当前难度存 `candy.difficulty`。
- **解锁条件**：普通模式最后一关有星（`hardUnlocked`）。启动时若存的是 hard 但已不满足条件 → 静默回落 normal。
- 云存档/排行**只记普通模式**（后端暂无难度字段），困难进度只在本机。
- 困难关卡怎么变难是三消内部的事，地图层不感知——切换难度只是换进度 + 重定位镜头。
- 三消进行中（`playing`）或小人在走（`walk`）时禁切。

### 3. 云同步（`cloud.ts`——「本地是真相，网络尽力而为」）

- **启动流程**：`login()`（wx.login 拿 code → `POST /game/api/auth/login` 换 JWT + playerId，token 存本地）→ `flush()` 补传离线队列 → 上报邀请人 → 开分享 → `pull()` 云存档 → 同步资料 → 体力 `sync()`。**任何一步失败都不影响本地游玩**。
- **存档合并**：`GET /game/api/progress` 拉云端进度，与本地**逐关取大合并**（星取大、分取大、解锁取大），合并结果既写本地也 PUT 回云端（把本地独有的历史进度推上去）。401 → 清 token 转纯本地。
- **结算上报**：每局 `POST /game/api/level/result`（level/win/stars/score/moves/durationMs），失败进离线队列，下次启动补传（队列上限 200 条）。
- **资料同步**：改昵称/头像先 `PUT /game/api/player/profile`，**后端确认成功才写本地**，失败回滚并把后端的违规提示 toast 给玩家（昵称违规词由后端检测，本地只查长度≤12、去空白、控制字符）。
- 后端基址由构建期常量注入，仓库里不写地址；空串时云同步整体关闭、纯本地可玩。

### 4. 微信专属能力（`wxFeatures.ts`——非微信环境全部安全降级 no-op）

- **分享**：`wx.onShareAppMessage`，卡片 query 带 `inviter=<playerId>`；启动时从 `wx.getLaunchOptionsSync().query.inviter` 读出「我是被谁邀请来的」，登录后上报后端（好友系统二期，失败静默）。
- **好友排行**（微信硬性限制，绕不开）：主域读不到好友数据。做法是主域把本人总分/总星/最高关 `wx.setUserCloudStorage` 写进托管 KV（value 必须是 `{wxgame:{score, update_time}}` 形状微信才认）；好友数据由**开放数据域**脚本读、画到 sharedCanvas，主域只能把整张 canvas `drawImage` 贴到屏幕上。

### 5. 全 Canvas UI 的点击处理（这套机制值得原样搬）

- **命中区域登记**：每帧绘制 UI 时，把每个可点元素 `{x,y,w,h,onTap}` push 进 `hits` 数组；触摸抬起时从**后往前**找（后画的在上面，天然 zIndex）。零 DOM、零节点树，代码量极小。
- **触摸分流**（`game.ts`）：按下时记 `drag.ui = shell.covers(x,y)`（落在 UI 控件上、或非首页、或低于导航上沿）；拖动时 UI 区域交给 `shell.scrollBy`（列表滚动）、否则交给相机（地图拖动）；抬起时位移 ≤6px（TAP_SLOP）才算点击，UI 命中执行动作，否则换算世界坐标做关卡命中 `hitLevelNode`。
- **PointerRouter 栈**：小游戏只有一条全局触摸流（wx.onTouch\*），地图页是默认消费者，打开三消时 push 三消的消费者、关闭时 pop。玩法和外壳不抢事件。
- **开关震动**：点击命中的瞬间，若设置开了震动就 `host.vibrate()`（短震）。

### 6. 主题与占位系统（`ui/theme.ts` + `ui/draw.ts`）——美术出图前后代码不变

- 所有外观集中在 `THEME`：底色、字体、三种底板配色（wood 木棕 / selected 金黄 / idle 灰）、图标映射。
- **每个绘制函数都是「有切图画切图，没切图画颜色/emoji 占位」**：`drawBox`（九宫格拉伸木纹 or 渐变+描边+顶部高光的圆角矩形）、`drawIcon`（切图 or emoji 🏠🏆📖⚙️❤️＋🐾🔒⭐）、`drawAvatar`（图片 or emoji 圆 + 木环描边）、`drawText`（超宽截断加省略号）、`drawSwitch`（设置开关）。
- 美术出图后只需把切图放进包里、在 `theme.images` 填路径，**布局和逻辑一行不改**。木板类贴图按九宫格拉伸（四角不拉伸），一张图用于不同长短的按钮。
- 这是「先跑通灰盒、美术后补」的关键实践，和萌宠拼拼乐的里程碑节奏一致。

### 7. 安全区 / 异形屏适配（真机必踩）

- `topInset`（顶栏让位）：`max(statusBarHeight + 40, 胶囊按钮.bottom + 6)`。**必须有保底值**——开发者工具里 `wx.getMenuButtonBoundingClientRect()` 可能拿不到。
- `bottomInset`（底部让位）：`safeArea ? height - safeArea.bottom : 0`（iPhone Home 横条）。
- 画布是 `wx.createCanvas()` **第一次调用**返回的上屏画布；之后调用都是离屏画布。
- 逻辑宽高用 `wx.getWindowInfo().windowWidth/Height`，全程 CSS 像素，只在 setTransform 时乘 devicePixelRatio。

### 8. 地图渲染与镜头（首页中央）

- 地图数据来自通用地图编辑器导出的 `.map.json`（关卡节点=带自增数字字段的组件；数据里的大图构建时抽成 `images/` 文件，**game.js 超 2000KB 开发者工具不编译**，这是硬限制）。
- **布局**：`camera.scale = 屏宽 / (9 × 格子宽)`——一屏恒定 9 格宽，地图只纵向长。相机 clamp 在 `[0, map.widthPx - 视口宽]`。
- **focus**：启动/切难度/结算后把当前进度关（`focusLevel`）的节点居中。
- 叠加层从底到顶：章节横幅 → 关卡状态（数字/锁/光环/星级）→ 通关小人 → 云。节点状态换算要和组件绘制同一套（视差、爬坡透视、呼吸/浮动动画），否则数字会和节点错位。

### 9. 玩法接入点（首页和三消的唯一接口）

```ts
type OpenLevel = (level: number, cbs: { onResult(r: LevelResult): void; onClose(): void }) => void;
type OpenLevelFactory = (deps: { host; router; soundOn(): boolean }) => OpenLevel;
```

- 首页只管：解锁判断 → 扣体力 → `openLevel(level, {onResult, onClose})`。
- `onResult`：通关返还体力、记进度、toast 星级、排「小人走到下一关」、上报云端/好友榜。
- `onClose`：恢复 `playing=false`、**重设画布尺寸和相机**（玩法可能把共享画布 resize 成自己的尺寸）、播放行走动画或 focus。
- 萌宠拼拼乐把 `createOpenLevel` 换成 Cocos 场景加载即可，`onResult/onClose` 语义不变。

### 10. 进关流程（时序）

```
点关卡 → playing=true（防重复点）→ tryConsume()（异步，可能等后端）
  ├─ 失败 → playing=false，toast「体力不足，M:SS 后恢复」
  └─ 成功 → openLevel(level)
       ├─ 玩法 onResult：win→返还体力/记进度/toast★/排行走动画/上报（仅普通模式）
       └─ 玩法 onClose：playing=false、恢复画布与相机、小人走到新关 or focus
```

## 七、踩过的坑（微信小游戏真机/工具，按修复时间）

1. **game.js 超 2000KB** 开发者工具上传时不做编译处理（白屏）→ 地图里的大图从 data URL 抽成独立图片文件，按 sha1 命名放 `images/`。
2. **开发者工具启动即崩**：`canvas.style` 在小游戏环境是 undefined，不能当浏览器 canvas 用。
3. **图片加载不能依赖 `decode/naturalWidth/complete`**（微信里行为不一致），用自封装的 ready 判断 + 加载完回调重画。
4. **顶栏被胶囊按钮挡住**：`getMenuButtonBoundingClientRect` 在工具里可能拿不到，必须 `状态栏+40` 保底再校正；底部要给 Home 指示条让位。
5. **小游戏没有 DOM 输入框**：昵称编辑用 `wx.showKeyboard` + `wx.onKeyboardConfirm`，取消返回 null；确认框用 `wx.showModal`。
6. **`wx.getStorageSync` 可能返回非字符串**（存过对象时），读的时候统一归一化成字符串再 JSON.parse。
7. **好友数据主域读不到**（微信规定）：只能开放数据域画 sharedCanvas，主域整张贴图。

## 八、自测与构建（不用每次开开发者工具）

- `scripts/minigame-smoke.html`（浏览器宿主冒烟）+ `minigame-wxsim.html`（模拟 wx 环境）：不开微信工具就能验证页面逻辑。
- 体力/难度等纯逻辑都有 vitest 单测（`tests/stamina.test.ts` 等），改规则先跑测试。

## 九、给萌宠拼拼乐的落地建议

1. **直接照搬的**：数据模型（Progress/Profile/Settings/StaminaRule）、存储 key 设计（难度分 key）、体力规则与双轨策略、云同步协议与「取大合并/离线队列」、微信适配的坑清单（§七）、进关时序（§四.10）、`openLevel(onResult/onClose)` 接口语义。
2. **换成 Cocos 做的**：渲染层。Canvas 手绘 + hits 命中区 → Cocos 节点/Button/Widget；相机 clamp/focus → Cocos Camera + 滚动限制；建议仍保留一个「Host」式的平台抽象层，把 wx.\* 隔离掉，方便浏览器自测。
3. **建议延续的流程经验**：先 emoji/颜色占位跑通全部交互（主题集中一个文件，切图后填路径零改动）→ 每个系统配纯函数单测 → 浏览器冒烟 + 开发者工具双层自测。
4. 排行页的三态（加载/空/失败可重试）、「我的排名」吸底、好友榜走开放数据域——这些产品细节已经验证过，别漏。
5. 美术规格两边是同一套（木质底板 + 金黄选中 + 灰未解锁 + 九宫格拉伸），切图可以直接沿用 `theme.ts` 的 `images` 槽位设计。
